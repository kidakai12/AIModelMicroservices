# Deploy on Render (free / limited tier)

Use Render to test your backend on the public internet before paying for DigitalOcean.

## What gets deployed

| Resource | Name | URL pattern |
|----------|------|-------------|
| PostgreSQL | `iot-user-db` | Internal only (linked to user-service) |
| Web (Docker) | `iot-user-service` | `https://iot-user-service.onrender.com` |
| Web (Python) | `iot-training-service` | stub — `.../api/v1/training/` |
| Web (Python) | `iot-model-zoo-service` | stub — `.../api/v1/models/` |
| Web (Python) | `iot-toolbox-service` | stub — `.../api/v1/toolbox/` |

There is **no nginx gateway** on Render in this blueprint. Each service has its own URL (fine for testing).

## Prerequisites

1. [Render](https://render.com) account (GitHub login is easiest)
2. This repo pushed to **GitHub** (Render deploys from Git)
3. Payment method may be required on the account even for free services (Render policy — check current terms)

## One-click deploy (Blueprint)

1. Push your code to GitHub.
2. In Render Dashboard → **New** → **Blueprint**.
3. Connect the repository.
4. Render detects `render.yaml` at the repo root → **Apply**.
5. Wait for builds (user-service Docker build takes a few minutes the first time).
6. Open **iot-user-service** → copy the public URL.

### After deploy

**API base URL:** `https://iot-user-service.onrender.com`

| Action | Request |
|--------|---------|
| Register | `POST /api/v1/auth/register` |
| Login | `POST /api/v1/auth/login` |
| Profile | `GET /api/v1/users/me` + `Authorization: Bearer <token>` |
| Docs | `https://iot-user-service.onrender.com/docs` |
| Health | `https://iot-user-service.onrender.com/health` |

**Stub check:**

```text
GET https://iot-training-service.onrender.com/api/v1/training/
```

## Free tier limitations (important)

- **Sleep:** Free web services spin down after ~15 minutes without traffic. The first request after sleep can take 30–60+ seconds (cold start).
- **Postgres:** Free database has storage/connection limits; review [Render pricing](https://render.com/pricing). Free DB offerings may change or expire — check dashboard.
- **Build minutes:** Monthly build time cap on free accounts.
- **Multiple services:** This blueprint creates **4 web services + 1 DB**. You can delete the three stub services in the dashboard to save free slots and reduce cold starts.

### Recommended minimal free setup

Keep only:

- `iot-user-db`
- `iot-user-service`

Delete or do not deploy `iot-training-service`, `iot-model-zoo-service`, `iot-toolbox-service` until you need them.

To deploy only user-service + DB, use [render.user-only.yaml](../../render.user-only.yaml) instead of the full `render.yaml`.

## Environment variables (dashboard)

Set or update under **iot-user-service** → **Environment**:

| Variable | Notes |
|----------|--------|
| `JWT_SECRET_KEY` | Auto-generated by blueprint; rotate in production |
| `CORS_ORIGINS` | Add your frontend URL, e.g. `https://myapp.vercel.app` |
| `DATABASE_URL` | Auto-linked from `iot-user-db` (do not paste External URL unless debugging) |
| `DATABASE_SSL` | Set `true` only if you use an **external** Postgres URL with SSL required |

Migrations run automatically on each deploy (`alembic upgrade head` in the Docker start command).

## Manual deploy (single service, no Blueprint)

1. **New** → **PostgreSQL** → name `iot-user-db`, plan Free.
2. **New** → **Web Service** → **Docker**, root directory `services/user-service`.
3. Environment → link `DATABASE_URL` from the database.
4. Add `JWT_SECRET_KEY` (random string).
5. Deploy.

## Local vs Render

| | Local (`docker compose`) | Render |
|--|--------------------------|--------|
| Gateway | `localhost:8080` | Per-service URLs |
| Postgres | Container | Managed Render DB |
| Cold start | No | Yes (free tier) |

## Troubleshooting

**Build fails on user-service**

- Check Render build logs. Ensure `rootDir` is `services/user-service` and Dockerfile path is correct.

**`alembic upgrade` / DB connection errors**

- Confirm `DATABASE_URL` is set from the **same region** database (internal connection string).
- If you manually set an External URL, try `DATABASE_SSL=true`.

**502 / timeout on first request**

- Free tier cold start — wait and retry, or upgrade to a paid plan for always-on.

**CORS errors from browser**

- Add your frontend origin to `CORS_ORIGINS` on `iot-user-service`.
